# Real-Time Hand Gesture Recognition

Machine Learning course project. Isolated hand gesture recognition on the
[IPN Hand](https://gibranbenitez.github.io/IPN_Hand/) dataset - classifying trimmed video
clips into 13 gesture classes - compared across three fundamentally different approaches:
landmark statistics, landmark sequences, and raw video pixels.


## Project description

The core question is: **landmark-based vs. pixel-based**, and
**classical vs. deep learning** - which wins on accuracy for hand gesture recognition, and
is the extra complexity worth it? 

| Approach | Models | Notebook |
|---|---|---|
| Landmark statistics (aggregated) | KNN, SVM (linear + RBF), Random Forest | `04_classical_models.ipynb` |
| Landmark sequences (RNN) | LSTM, GRU, BiGRU, BiLSTM | `05_lstm_models.ipynb` |
| Raw video clips (pixels) | 3D CNN from scratch, R(2+1)D-18 (pretrained) | `06_3dcnn_models.ipynb`, `07_1_kaggle_model3DCNN.ipynb`, `07_2_kaggle_modelR(2+1)D.ipynb` |

Landmark-based models use [MediaPipe Hands](https://github.com/google/mediapipe) to extract
21 hand landmarks per frame; pixel-based models train directly on raw video clips.
All ten models are scored with a shared evaluation module
(`src/evaluation/metrics.py`) on the same official test split, so results are directly
comparable. See `08_final_evaluation.ipynb` for the full joint comparison and conclusions.

**Headline result:** R(2+1)D-18 (transfer learning from Kinetics-400) achieves the highest
accuracy (0.941 weighted F1), about 5 points ahead of the best landmark model, BiGRU (0.888) -
which gets there with roughly a tenth of the parameters (3.0M vs 31.3M). Full breakdown,
confusion matrices, and per-class analysis are in `08_final_evaluation.ipynb`.

## Dataset

[IPN Hand](https://gibranbenitez.github.io/IPN_Hand/) ([GitHub](https://github.com/GibranBenitez/IPN-hand)):
long continuous videos (~2 min, ~3700 frames @ 30fps) of subjects performing a series of
hand gestures separated by pauses. Annotators marked the start/end of each gesture segment;
each segment is treated as one isolated sample.

- **13 gesture classes** (a 14th, "Non-gesture", is dropped): Point-1f, Point-2f, Click-1f,
  Click-2f, Throw-up, Throw-down, Throw-left, Throw-right, Open-twice, DblClick-1f,
  DblClick-2f, Zoom-in, Zoom-out.
- **~3,117 train / ~1,101 test gestures**, using IPN Hand's official train/test split
  (never re-split randomly - the same subject must not appear in both sets).
- **Class imbalance**: `Point-1f`/`Point-2f` each have roughly 5x more samples than the
  other 11 classes. The RNN and 3D CNN models correct for this with class-weighted losses;
  the classical models (KNN/SVM/Random Forest) are trained without reweighting, so macro F1
  (alongside accuracy) is reported everywhere to make the imbalance's effect visible. See
  `01_data_exploration.ipynb` for the full breakdown.

The raw dataset is not included in this repo - download it
from the link above and place it under `raw_data/raw/` (expects `Annot_*.txt`,
`Video_*.txt`, `classIdx.txt`, and five `frames*` folders, matching IPN Hand's original
layout).

## Setup

```bash
pip install -r requirements.txt
```

Notes:
- `mediapipe` is pinned to `0.10.9` - later releases (including `1.x`) removed the legacy
  `mp.solutions.hands` API that `src/data/landmark_extractor.py` depends on.
- Classical and RNN model training (`04_classical_models.ipynb`, `05_lstm_models.ipynb`)
  runs locally and auto-selects a GPU if available (`torch.backends.mps` on Apple Silicon,
  then `torch.cuda`, falling back to CPU).
- The two pixel-based models are trained on **Kaggle**, not locally - see
  `07_1_kaggle_model3DCNN.ipynb` / `07_2_kaggle_modelR(2+1)D.ipynb` and the note in
  `06_3dcnn_models.ipynb` for why.
- Download the IPN Hand dataset separately (see **Dataset** above) and place it under
  `raw_data/raw/`.

## Notebooks (review in this order)

1. **`01_data_exploration.ipynb`** - dataset structure, class balance, sample gestures.
2. **`02_test_landmark_extraction.ipynb`** - MediaPipe hand landmark extraction, tested on a
   sample of gestures.
3. **`03_clip_extraction.ipynb`** - extracts fixed-length raw video clips (16 frames,
   112×112) for the pixel-based branch.
4. **`04_classical_models.ipynb`** - KNN, SVM (linear/RBF), Random Forest on aggregated
   landmark statistics.
5. **`05_lstm_models.ipynb`** - LSTM/BiLSTM/GRU/BiGRU on landmark sequences, with
   architecture and hyperparameter comparisons.
6. **`06_3dcnn_models.ipynb`** - builds both pixel-based models, then loads and evaluates
   the results produced by notebooks 7.1/7.2 (training itself happens on Kaggle - see below).
7. **`07_1_kaggle_model3DCNN.ipynb`** / **`07_2_kaggle_modelR(2+1)D.ipynb`** - self-contained
   notebooks (no `src/` imports) that actually train the from-scratch 3D CNN and fine-tune
   R(2+1)D-18 on Kaggle's GPU. Moved off local CPU/MPS because a learning-rate sweep run to
   saturation needs many full training runs - ~270s/epoch locally vs. ~35s/epoch on Kaggle
   made that impractical. Their output (checkpoints, curves, predictions) is saved under
   `results/kaggleA/` and `results/kaggleB/` and loaded back into notebook 6.
8. **`08_final_evaluation.ipynb`** - joint comparison of all ten models, per-class analysis,
   confusion matrices, and final conclusions. 

## Demos

Two real-time webcam demo scripts are provided in `src/demo/`:

- **`realtime_demo.py`** - runs the trained BiGRU model (the best-performing landmark model,
  0.888 weighted F1). Webcam frame → MediaPipe landmarks → rolling buffer of 120 frames →
  velocity features → standardization → BiGRU → gesture prediction with temporal smoothing
- **`realtime_demo_r2plus1d.py`** - runs the trained R(2+1)D-18 model instead. Webcam frames
  → rolling buffer of 16 raw frames → resize/normalize → R(2+1)D-18 → gesture prediction.
  Noticeably higher latency than the BiGRU demo since the model is much heavier.

Both require the corresponding checkpoint (and, for the BiGRU demo, the feature scaler)
downloaded from the Google Drive link below and placed under `data/checkpoints/`. Run with
`python src/demo/realtime_demo.py` (or `_r2plus1d.py`) from the repo root; press `q` to quit.
